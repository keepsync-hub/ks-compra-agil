Por qué esta página está separada de la de Compra Ágil

El agente de Compra Ágil (resumen) está verificado end-to-end contra la API real de producción. Este segundo nicho usa una API distinta (api.mercadopublico.cl, la API clásica de Licitaciones), con su propio ticket y su propia cuota. Desde el 19 de agosto de 2026 el radar sí corrió contra esa API con un ticket válido: las oportunidades de arriba son datos reales, no una maqueta. Lo que sigue sin resolverse es el otro extremo — poder cotizar y entregar —, y esta página lo declara con la misma honestidad que la de Compra Ágil declara sus propios pendientes.

Estado de cada componente

El radar ya está verificado contra producción; el cotizador sigue bloqueado por falta de un catálogo de costos reales.

Insumos bloqueantes

El primero quedó resuelto; el que decide si esto se convierte en venta, no — detalle completo en licitaciones/PLAN.md.

1. LICITACIONES_API_TICKET — resuelto. El ticket existe y el radar corrió contra producción el 19-08-2026. Esa corrida corrigió varias suposiciones del código: el ítem del listado no trae comprador ni monto (solo la ficha los trae), el plazo de contrato vive en TiempoDuracionContrato, y esta API no expone los adjuntos ni las garantías de la licitación — las bases hay que leerlas en el portal. Queda pendiente cuidar la cuota: es de pocas llamadas al día.
2. Catálogo de costos reales de KeepSync para gestión documental. A diferencia de licencias Claude (precio de lista público de Anthropic ya cargado), acá no existe un precio externo que copiar: hay que definir qué plataforma se revende o implementa y a qué costo real (por usuario, por hora, por documento digitalizado) antes de que el cotizador pueda generar una oferta real.

Qué falta para operar en serio

  1. LICITACIONES_API_TICKET — solicitarlo y correr el radar contra la API real — hecho el 19-08-2026; los nombres de campo de licitaciones/src/lib/api.ts ya están corregidos según la respuesta real.
  2. Medir la cuota diaria del ticket — se agotó en la segunda corrida del día, lo que hoy impide correr el informe histórico del nicho. Sin esa medida no se puede decidir la frecuencia del radar ni el alcance del barrido histórico.
  3. Definir el catálogo de costos reales de KeepSync para gestión documental y completar licitaciones/config/company.json.
  4. Confirmar la fórmula de pricing (markup/IVA) para este negocio — el default en company.json.example es una plantilla razonable, no una decisión ya tomada.
  5. Correr npm run cotizar-licitaciones -- <codigo> contra una licitación real y revisar manualmente el PDF/PPTX generado.
  6. (Fuera de esta réplica) Diseñar un tercer skill para login + formulario del portal de Licitaciones, si se decide automatizar también ese paso.

La grilla de oportunidades la refresca npm run radar-licitaciones; el resto de la página está escrito a mano y no se actualiza solo. Las cifras del nicho (cuántas licitaciones de este tipo se declaran desiertas, cuántas se adjudican y a quién) todavía no existen: para eso falta correr el informe histórico, hoy bloqueado por la cuota del ticket.
