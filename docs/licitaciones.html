Agente de Licitaciones — Gestión Documental

Réplica del agente de Compra Ágil, para un segundo nicho: Licitaciones públicas (no Compra Ágil) que piden gestión documental, digitalización de procesos u oficina de partes. Mismo objetivo — monitorear oportunidades, cotizar dentro del tope y dejar todo listo para revisión humana — con una API, un producto y un modelo de costos distintos.

Oportunidades detectadas

Licitaciones públicas abiertas que mencionan gestión documental, digitalización de procesos u oficina de partes, según la última corrida de npm run radar-licitaciones. El estado de cada una es detectada: el radar solo observa — cotizar es un paso aparte (npm run cotizar-licitaciones -- <codigo>) y el envío de una oferta lo hace siempre una persona.

Ninguna licitación abierta de este nicho en la última corrida del radar, o el radar todavía no se ha podido correr contra la API real. Este bloque se llena solo al ejecutar npm run radar-licitaciones con un LICITACIONES_API_TICKET válido — hasta entonces no hay oportunidades que mostrar, y esta página no inventa ninguna.

Por qué esta página está separada de la de Compra Ágil

El agente de Compra Ágil (resumen) está verificado end-to-end contra la API real de producción. Este segundo nicho usa una API distinta (api.mercadopublico.cl, la API clásica de Licitaciones) y todavía no se ha corrido contra ella con un ticket válido — el código está escrito y revisado, pero sus resultados son, por ahora, una hipótesis de diseño, no una medición. Esta página lo declara con la misma honestidad que la de Compra Ágil declara sus propios pendientes.

Insumos bloqueantes

Ninguno resuelto todavía — detalle completo en licitaciones/PLAN.md.

1. LICITACIONES_API_TICKET. Distinto del ticket de Compra Ágil — se solicita en mercadopublico.cl/Home/Api. Sin él, el radar y el cotizador no pueden correr contra datos reales ni verificar si los nombres de campo asumidos en el código son correctos.
2. Catálogo de costos reales de KeepSync para gestión documental. A diferencia de licencias Claude (precio de lista público de Anthropic ya cargado), acá no existe un precio externo que copiar: hay que definir qué plataforma se revende o implementa y a qué costo real (por usuario, por hora, por documento digitalizado) antes de que el cotizador pueda generar una oferta real.

Qué falta para operar en serio

  1. LICITACIONES_API_TICKET — solicitarlo y correr npm run radar-licitaciones contra la API real; corregir los nombres de campo de licitaciones/src/lib/api.ts según la respuesta real.
  2. Definir el catálogo de costos reales de KeepSync para gestión documental y completar licitaciones/config/company.json.
  3. Confirmar la fórmula de pricing (markup/IVA) para este negocio — el default en company.json.example es una plantilla razonable, no una decisión ya tomada.
  4. Correr npm run cotizar-licitaciones -- <codigo> contra una licitación real y revisar manualmente el PDF/PPTX generado.
  5. (Fuera de esta réplica) Diseñar un tercer skill para login + formulario del portal de Licitaciones, si se decide automatizar también ese paso.
