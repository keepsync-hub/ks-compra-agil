Cómo funciona el agente, paso a paso

Un diagrama simple del flujo completo — desde que el radar detecta una Compra Ágil de licencias Claude hasta que una persona la envía — con foco en dos cosas: qué hace cada skill y en qué puntos exactos el agente se detiene y le pasa el control a una persona.

Ver también: página de estado · README.md · PLAN.md

El flujo completo

Tres pasos corren solos en el sandbox en la nube (solo lectura + generación de archivos, sin tocar el portal). Los últimos dos requieren un navegador real y quedan diferidos a una sesión de Claude Cowork en la máquina de la persona. El envío final nunca lo hace un script.

skill compra-agil-radar-claude
skill compra-agil-ofertar
checkpoint de revisión humana
acción que solo hace la persona

Los dos skills, explicados

Un skill de Claude Code es una carpeta con un SKILL.md (qué hace y cuándo usarlo, en lenguaje natural) más los scripts que ejecuta. El agente decide solo cuál skill activar según lo que la persona le pida — también se puede saltar directo al comando npm run correspondiente.

.claude/skills/compra-agil-radar-claude/

Radar — solo lectura

Busca Compras Ágiles publicadas que mencionen Claude/Anthropic, extrae condiciones y detecta organismos que reintentan. No requiere credenciales del portal, solo el ticket de la API.

Se activa cuando la persona dice
"corré el radar" "qué hay abierto de Claude" "revisá oportunidades nuevas"
Corre
  • npm run radar → scripts/radar.ts: oportunidades abiertas hoy.
  • npm run informe → scripts/informe-nicho.ts: barrido histórico completo.
Produce
  • data/<codigo>/{detalle.json, condiciones.json} — insumo para cotizar.
  • output/radar-ultima-corrida.md y output/informe-nicho-claude.md.
Nunca
  • Toca el portal ni pide aprobación — es de solo lectura de punta a punta.
.claude/skills/compra-agil-ofertar/

Ofertar — cotiza, y deja el formulario listo (sin enviar)

Genera la cotización de licencias respetando el tope y, en una sesión aparte con navegador, deja el formulario del portal completo con el PDF adjunto — sin enviarlo nunca.

Se activa cuando la persona dice
"cotizá 1614-47-COT26" "preparame la oferta para <código>"
Corre
  • npm run cotizar -- <codigo> → scripts/cotizar.ts: valida tope y genera PDF/PPTX.
  • login.ts / form-fill.ts — solo desde la sesión de Cowork local (ver más abajo).
Requiere
  • config/company.json con costos reales (el agente no inventa precios).
  • CLAVE_UNICA_RUN / CLAVE_UNICA_CLAVE en .env, solo para los pasos 4–5.
Nunca
  • Cotiza sobre el tope, ni hace clic en enviar/confirmar el formulario.

Dónde entra la persona

Tres puntos exactos donde el agente se detiene y espera a un humano — ninguno es opcional.

Checkpoint 1 — después del paso 3

Revisar la cotización antes de seguir

El PDF/PPTX en output/<codigo>/ queda listo, pero es la persona quien confirma que el precio, el plan y las condiciones son correctos antes de pasar al portal.

Checkpoint 2 — antes de los pasos 4–5

Abrir una sesión de Claude Cowork en la máquina local

claveunica.gob.cl y mercadopublico.cl le devuelven ERR_CONNECTION_RESET al navegador headless de este sandbox en la nube (confirmado repetidas veces; curl con el mismo User-Agent sí conecta — es un bloqueo de fingerprint/WAF del portal, no un bug del código). Por eso el login y el formulario no se intentan desde acá: la persona los completa en otra sesión, con Claude Cowork corriendo en su propia máquina (navegador real, su red), usando los PDF de output/ como insumo.

Checkpoint 3 — después del paso 5, siempre

El clic de enviar, en el portal, lo hace la persona

form-fill.ts deja el formulario completo y adjunto, y guarda formulario-listo.png como evidencia — pero nunca busca ni hace clic en un botón de enviar/confirmar. Enviar una oferta es un acto público y vinculante ante el organismo comprador: eso lo confirma siempre un humano, sin excepción.

Guardrails relacionados (ver CLAUDE.md para el detalle completo): nunca se cotiza por sobre el tope presupuestario, nunca se inventan precios sin config/company.json real, y ante CAPTCHA o bloqueo del portal el agente se detiene y pide intervención humana en vez de reintentar a ciegas.

Esta página documenta el flujo tal como está implementado hoy — si el código cambia (por ejemplo si algún día el login sí corre desde la nube), actualizarla junto con el cambio.
